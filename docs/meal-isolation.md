# 五餐独立数据规则

适用于 v1.4.5。五餐隔离从 v1.4.0 引入，兼容此前使用共享数据的数据库。

## 隔离范围

早餐、午餐、晚餐、下午茶、宵夜各自保存转盘选项、分类、商家和餐品、备注、次数、排列顺序、做饭食材、采购清单、烹饪菜单及勾选状态、做饭总次数。增删改、排序、Pick、批量转入和完成本餐只改变当前餐。

语言是全局产品设置，中英文切换对整个 App 生效；用户填写的名称和备注不自动翻译。原有页面内容、宵夜点外卖进入零食清单的路由、转盘和抽牌玩法保留。

子页面显示当前餐次。首页数据统计按五餐选择器切换，不混算其他餐。首页选择入口后，整个下游操作路径绑定这一餐。

## 升级时如何处理现有数据

旧版没有保存每条历史记录属于早餐还是午餐，不能可靠地重新分配。为保留现有信息，数据库 3→4 将整份旧数据复制为五份相同的起始数据，随后各餐独立修改。

- 分类名称、用户备注、排序和已经记录的次数均保留。
- 未完成购物车和烹饪菜单也复制，已采购/已完成状态保留；以后各餐独立处理。
- 旧版已删除或删空的数据按现状复制，初始化标记随餐迁移，不恢复已删除内容，不回填手机中没有的营养选项。
- 迁移不把复制出来的历史次数作为新增吃饭记录；统计页展示单餐，不提供五餐相加的历史总数。
- 新安装为五餐分别导入同样的初始资料：每餐 21 组、61 条餐品和 6 条食材，次数全为 0。

## 实现边界

Room 数据库升级到 4，FoodGroup 新增 mealId。条目和清单通过所属分类确定餐次。晚餐保留旧 ID，另外四餐 ID 加稳定前缀；内部采购与菜单会话标识也独立。其他业务表结构保持，语言设置全局共享。

MealRepository 每个实例固定一餐，所有快照均过滤该餐，所有 ID 写入必须经过餐次归属检查。排序列表需完整匹配当前餐范围；清空菜单、完成计数、去重和批量转入均在事务内按餐执行。迁移由 Room 事务一次性提交，兼容 schema 1、2、3 的完整升级链，不采用破坏性重建。

ViewModel 在点击时捕获写入对应的仓库，避免挂起后切换餐次导致写错；切餐先清掉旧快照，旧观察结果无法重新覆盖新餐。不同餐的编辑弹窗、抽牌和做饭展开状态分别管理。

相关回归测试位于 `app/src/androidTest/java/com/mealpick/app/data/` 与 `app/src/androidTest/java/com/mealpick/app/ui/`。正式安装包及发布说明见 GitHub Releases。
